# Requirements engineering
## Instructions
- User stories: "As a <role>, I want <goal> so that <benefit>."
- Each story must pass INVEST (Independent, Negotiable, Valuable, Estimable, Small, Testable).
- Prioritize with MoSCoW. Only Must items are MVP.
- Keep functional (FR-###) and non-functional (NFR-###) requirements separate. NFRs cover usability, performance, security, accessibility, maintainability.
- Every requirement is unambiguous and testable. Flag vague words ("fast", "easy", "user-friendly") and replace them with measurable criteria.
- Maintain a traceability table: Story → FR/NFR → acceptance criteria → test.
- Record assumptions, constraints, and out-of-scope items explicitly.
- When reviewing, list missing, conflicting, or untestable requirements. Don't silently fix them.
